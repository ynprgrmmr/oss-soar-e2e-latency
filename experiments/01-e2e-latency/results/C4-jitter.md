# C4-jitter（Wazuh Active Response で直接 CHR、試験前ランダム待ちあり）30 回の結果

最初の C4（`C4.md`）は試験の開始が agent の 2 s 周期の読み取りと位相同期し、D_detect が偏った。
試験前に 0〜4 s のランダム待ちを入れて再計測したのがこの結果で、**C4 の正式な値はこちらを使う**。

- 実施: 2026-11-24 05:37–06:17 UTC、バッチ `batch-C4-jitter-20261124T053753Z`
- 構成: C4 と同じ（rule 100510 → wazuh-execd → `soar-chr-block` → CHR REST、Shuffle 連携は計測中のみ無効）
- 計測後: ossec.conf を C1 構成に戻した（バックアップとバイト単位で一致、Shuffle 連携 1 件、AR の設定 0 件）。
  確認用の 1 試験（run 7e7d6d2b、`C1-verify`）で Shuffle 経路が動き AR が動かないことを確かめた（E2E 4,290 ms）

## C1 との比較

| | C1（Shuffle 経由） | C4-jitter（AR 直結） | 差 |
|---|---|---|---|
| E2E p50 | 5,302 ms | 1,662 ms | **−3,640 ms（−69%）** |
| E2E p95 | 7,754 ms | 2,421 ms | −5,333 ms |
| E2E max | 8,714 ms | 3,088 ms | — |
| 検知後 p50 | 3,937 ms | 184 ms | −3,753 ms |

- **E2E の分布は完全に分かれた**: C4-jitter の最大（3,088 ms）は C1 の最小（3,683 ms）より短い（Mann-Whitney U = 900、p = 2.9e-11）
- **D_detect は C1 と差がない**（Mann-Whitney p = 0.19）。検知経路が同じという前提どおり。ランダム待ちで偏りが消えたことの確認にもなる
- **SOAR 層（integratord + Shuffle）のコストは中央値で約 3.6〜3.8 s**。C4 の D_dispatch は 54 ± 2 ms と極めて安定
- CHR 側（D_api・D_enforce）は 3 条件とも同じ水準。D_api の二峰性（約 24 ms と約 275 ms）は経路によらない
- C4-jitter の E2E は D_detect（agent の 2 s 周期の読み取り）でほぼ決まる。下限 約 0.3 s、上限は 2 s 周期の待ち + 検知後 約 0.2 s
